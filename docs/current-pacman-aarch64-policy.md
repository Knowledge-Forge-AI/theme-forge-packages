# Current AArch64 pacman preparation

Status: isolated source preparation; not adopted or natively qualified.

The maintainer approved the narrow product build/client operating policy on November 5. The earlier original SDK probe at [run 42033829642](https://github.com/Knowledge-Forge-AI/theme-forge-packages/actions/runs/42033829642) qualified its exact source, signed Arch Linux ARM root and 139 pinned packages. That result does not qualify this new SDK lease, product builder, mounts, account creation or installed clients.

The current-only producer builds Burst and Nebular on the native public ARM host. Loom and Solar keep one x64 construction source in the same original main-push campaign. The ARM job starts after the native jobs and verifies the original provider, artifact ZIP, receipt, custody and exact package bytes before reuse. Its raw replicas carry no construction or signing authority. Production routing selects the canonical x64 package and copies the same signature to both architecture repositories.

The new client is pacman-aarch64 on ubuntu-24.04-arm. Its SDK reconstructs the frozen inputs offline, creates the fixed guest account at the verified runner numeric identity and uses the approved role profiles. Builders and repo-add have zero capabilities and read-only roots; only installer/client root phases receive the existing seven capabilities. Application probes verify zero effective, permitted, inheritable and ambient capabilities. Workers have no network or shared IPC.

Only a per-product output tree is writable. Client output remains untrusted: owned writers stop before no-follow, ownership, stable-identity and schema checks. Private fixture signing stays on the host outside all workers. No production signing key or environment protection changes.

Existing guard, locked-Python, key and environment approvals remain recorded. This source preparation grants no canonical writes, adoption, hosted campaign, signing invocation or publication. Fresh original R qualification, the paired source-pin refresh, all six P clients and native-three GUI qualification remain required before publication. Historical defaults and the five earlier client paths retain their existing contracts.
