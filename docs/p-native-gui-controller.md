# Native Linux GUI qualification controller

This candidate route is a test-only adaptation of the authenticated Nebular smoke harness. It preserves the installed payload, public wrapper, released application arguments, scenario receipt checks and required failure outcomes. The Linux entrypoint and process-control harness change explicitly. Darwin keeps the existing public-wrapper adapter.

## Source and launch binding

The native validation job builds the existing locked predicate context. Its exact Python interpreter verifies the actual buildFHSEnv source, container-init producer, declared wrapper derivation, product runtime closure and namespace defaults. It emits source-bound observer inputs; these inputs grant no qualification or publication authority.

Immediately before each GUI launch, the same harness Node process authenticates the actual wrapper and stages a separately named observer in an owner-only directory. The observer replaces only the terminal exec with a NUL-delimited argument print. It uses the same frozen application arguments, working directory and environment as the subsequent real wrapper spawn. Readbacks bind source bytes, resolved wrapper, file identity and staging-directory lifetime. Observer execution has a ten-second deadline, a one-MiB live output bound and bounded cleanup of its exact owned process.

A same-process resolver handle is required before spawning the public wrapper. Saved JSON facts cannot replace that handle. The Python controller independently binds the resulting monitor executable, exact fresh argument vector, parentage, namespace, pidfds and application identity. It echoes the fresh launch digest in every response. No static monitor argument vector or numeric-PID fallback is accepted.

## Completion and evidence

For C-signal, the controller records the application SIGTERM witness separately from the monitor's expected code 143 with no signal. Ordinary scenarios require the normal zero exit. The unchanged qualified lease/watchdog is armed only immediately before the bounded C-signal stop/terminate/continue transaction. Its ARMED acknowledgement precedes SIGSTOP; its 40-second deadline is not used for the whole GUI scenario. Ordinary B/C records carry null watchdog and signal-witness fields. While the controller is alive, failure cleanup uses only revalidated exact pidfds. Identity loss is fatal; without an armed lease, application cleanup may remain unproven and disposable hosted-runner teardown is the final recovery boundary.

The bridge retains its response record outside disposable application scratch. The consumer checks closed schemas, source identities, a 32-hex nonce, the fresh launch digest, ordered BOUND/TERMINATED/FINALIZED phases, signal witness, cleanup and exact controller exit. A parser result alone grants no native or publication authority.

On failure, the bridge closes controller input and waits for bounded controller cleanup while monitor identity remains available. It stops its owned monitor only after the controller exits or its cleanup grace expires. An unconfirmed owned exit remains a failure.

The C-signal stop/terminate/continue transaction and its signal-phase receipt checks remain bounded by 35 seconds. After the controller disarms the watchdog and emits `TERMINATED`, it retains a separate finite 22-second post-`TERMINATED` finalization deadline for the existing bounded orphan observation, `FINALIZED` response wait and scheduling margin. The bridge allows 38 seconds for the response, below the qualified watchdog's 40-second limit. The 22-second post-`TERMINATED` window is not part of the 35-second signal-phase budget; no total signal-plus-finalization bound of 35 seconds is claimed.

## Verification boundary

Pure Python and Node fixtures exercise protocol, source joins, FIFO refusals, directory drift, bounded I/O and cleanup decisions. They do not prove native Linux kernel or GUI behavior. Later owner approval covers the reviewed GUI, observer and headless-WebKit campaign; campaign 41192208654 succeeded on Darwin and Linux ARM64 but its x86_64-linux C-signal harness failed. Source adoption and the resulting public native qualification remain separate evidence gates, and the partial campaign is not a release result. Production signing and deployment remain separate gates.

The Node resolver fixtures require P_GUI_FIFO_FIXTURES to name an owned fresh directory containing four FIFO leaves: fifo-before-wrapper, fifo-before-observer, fifo-after-wrapper and fifo-after-observer. The test runner creates these with its existing Python runtime; tests consume them and remove their fresh scratch. NEBULAR_SMOKE_SOURCE selects the authenticated tracked smoke source for adapter fixtures.
