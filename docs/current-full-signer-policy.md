## Closed post-frame diagnostic policy proposal

The observed full-signer failure at P 814aa40a / original run 41754668827 is WORKER_NONZERO_EXIT after POST_FRAME. Source/image preparation and the isolation handshake completed; no signing or client acceptance followed. Host container and image cleanup completed, while private C6 cleanup is not established by those observations.

The prepared extension adds one optional post_frame_diagnostic object only to a failed-closed host summary for that exact host-owned phase and error. It reports a fixed record state, high-level worker step and closed error label, plus an untrusted_worker_claim marker. It is diagnostic evidence and cannot change a gate, signing result, custody decision or publication authority.

The worker tracker is per invocation and in memory. It marks private module import, frame read, signing runtime, custody checking, public verification, export and receipt immediately before existing operations. A fixed unavailable value handles missing metadata. The adopted baseline vocabulary has nine step values, 61 code values and four record states. The separately prepared runtime-operation refinement below expands only the step vocabulary; it is not active until its distinct owner disposition. The code values are 43 exact existing refusal labels, 17 fixed builtin-exception-family labels and UNCLASSIFIED. Key- and passphrase-specific refusal labels plus STDIN_FRAME_NUL, STDIN_FRAME_BOUNDS and STDIN_FRAME_TRUNCATED are excluded. STDIN_FRAME_FORMAT tests only the fixed 16-byte header length and magic, without inspecting payload bytes. Exceptions outside the selected families or with unlisted exact string codes collapse to UNCLASSIFIED; no exception text, args, class name, path, identifier, payload, length or private key/passphrase value is forwarded.

The host independently validates exactly one nonempty ASCII worker failure line of at most 4096 bytes from its existing bounded stderr buffer. Duplicate keys, unexpected fields, malformed or multiple records, CR/NUL/non-ASCII data and unknown labels yield fixed unavailable output. This failure path adds an invocation of the existing bounded one-second drain, including its interruption window; timeout limits remain unchanged. It does not retain the raw buffer. Existing handshake worker_error_code and worker_error_detail remain WITHHELD_POST_FRAME; the worker's own post-frame outer error_code is also fixed to that value.

This is a deliberate, bounded declassification from an untrusted worker. Remaining protocol labels (including PROTOCOL_READ_BOUND), generic exception families and signing-outcome labels can correlate with private-input properties or key/passphrase validity even though private values and key-specific labels are excluded. Excluded labels collapse to UNCLASSIFIED; that category and its step can still narrow the possibilities. The destination is the failed job's public Actions log, so these closed labels are public disclosure under its existing retention. Finite labels do not make the claim trusted or eliminate covert signalling. Only one closed object may appear per failed invocation. Existing log retention applies; no raw-data retention, file/channel, dependency, privilege, network, timeout limit or key change is included.

For the adopted baseline extension, ProtectedSigningRuntime, source closure/authentication, protocol IO, Linux isolation, default-bridge ownership/teardown, the secret-frame emitter, successful receipts and the original operation/zeroization/cleanup sequence remain unchanged. Its SIGNING_RUNTIME step spans the entire protected runtime. The separately prepared operation refinement below narrows that axis without identifying a root cause. Child/docker stderr or incomplete collection can yield an unavailable record. A repeated unexplained result stops rather than authorizing a blind successor.

Activation requires the exact owner policy disposition and fresh original R, signing/client and same-source GUI qualification within the existing finite allowance. Historical or pure fixture evidence never supplies native acceptance. This proposal itself does not authorize production publication.

This step axis partially supersedes the baseline privacy rationale for excluding key- and passphrase-specific refusal codes. RUNTIME_IMPORT_CI may correlate with a failed import or rejected key topology. A first signing-operation marker may correlate with a passphrase rejection. These public correlations are deliberately admitted coarse information, even though one marker covers many unrelated refusals and is not a credential verdict. Values and raw diagnostics remain withheld; no claim of zero information leakage follows.

Ownership is attached to the original error before the optional diagnostic calls. If those calls are interrupted, the replacement exception receives the same runtime ownership before propagating.
